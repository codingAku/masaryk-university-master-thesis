TOUCAN: The project is the replacement for obsolete application CARL. This is mainly internal tool used for line configuration and calibration of instruments. The manufacturing of spectrometers is done using Toucan, mainly for OES. It is still under development for XR instruments. 
The application has several logical parts:
- Master Knowledge: The instruments have their own Instrument Knowledge, that includes their configuration. This information is based on master knowledge, it is like a toolbox of information to build specific instrument knowledge. Only analytical experts can edit master knowledge. Operators and manufacturing engineers cannot make changes to master knowledge.
- Define instrument: In this part, people who work with Sales department define the an isntrument based on requests of customers. Customers may whave some special requests on ranges of detection for elements. These requests are called Non-Standard Requests, known as NSR. Employees with MarketingAnalyticalExpert, SalesAdmin and SalesEngineer roles know about this information. However, only MarketingAnalyticalExpert people define the NSRs.
- Manufacture instrument: In this part, defined instruments are already in manufacturing, and operators, manufacturing engineers, and analytical experts work on building it. There are several parts that they do during the manufacturing workflow. These include Setup, Quality Control(QC), Quality Assurance (QA), Calibration, Validation, and then Reporting, and then Archiving. What does all of that mean? 
During setup, we export the configuration of the instrument to a different application called OXSAS. This application is actually what is running in Customer PC, which is the PC that is controlling the instrument itself. Customer PCs are shipped with the instruments to the customer, and customers are using this application called OXSAS to continue using the instrument. Toucan is only used during the manufacturing, where we make the experiments, where we do quality assurance, quality control, where we build the curves, etc., etc. But once the instrument is ready, customer is using Oksas application to actually control the instrument. So in setup screen of Toucan, we are creating the Oksas database, and then we are sending the instrument configuration to Oksas. And then the manufacturing engineers or the operators are making measurements using the Oksas, and then these measurements are imported back to the Toucan, and Toucan uses these measurements to actually build the curves. 
In Quality Control(QC), you just create some lines based on mounted detectors, and then send them to application OXSAS. You get to check if mounted detectors are functional at all. 
In Quality Assurance, you export some lines based on elements, and then you check if the instrument is able to detect correctly the concentrations of elements.This is where the MVR calculation comes to play.
In spectrometers, there are detectors, and these detectors detect some intensity of light, and then this light is converted into concentration of elements. This is the basic principle of spectrometers that work on optics. So, in the calibration part, we are building from lines the curves. The curves mean the graph where x-axis is the concentration and y-axis is the intensity. we measure some samples using OXSAS, and then we import these measurements to Toucan, get the intensity measurements from lines, and then we build the curves which show us the concentration of elements based on the intensity. This is one of the biggest jobs of Toucan. And then, this process, this whole process is actually called MVR. We have two screens dedicated for this job. One of them is full MVR where only analytical experts can use, and they go there and they just experiment with samples or interferences, additive or multiplicative interferences, while building the curves. They do the calculation. Toucan does this calculation, and then they are able to save the curve. And once the curve is saved, you go to compute screen in Toucan.
nce you are in the compute screen, the first selection you can do is select a quality. Quality is literally what we measure with an instrument. For example, low alloy steel is one quality, but in the Toucan domain, they are called qualities, and there are several ones which are already existing in master knowledge. And then when you select quality, there are several curves for different elements in a quality based on the instrument configuration and the master knowledge. And these are the curves that we just built in full MVR and then saved. But in compute screen, which is accessible to also manufacturing engineers and operators, you can see the actual curve, the graphical representation of the curve, where the dots on the curve are the samples, measurements more precisely, measurements on samples, and then x and y-axis as we talked about before. And there is also one part we call the check curve, and it is actually talking about the properties of the curve. In a separate document, you can find about these rules of check curve, and you can find how it is okay or not okay, or how it is presented in Toucan. And this is called MVR rules.
