1 INTRODUCTION
1.1 Purpose 
The purpose of this CRS is to document the requirements of all stakeholders involved in the whole lifecycle of the instrument manufacturing and development through Toucan software.
1.2 Scope
The scope of this CRS is OES and XRF, UniquantMaster/ Uniquant; notably out-of-scope are:
* Full support for XRD systems; (note: XRD has some overlap with XRF, this overlap is supported)
* (further) automation of calibration.
2 SYSTEM DESCRIPTION
2.1 System Context
The context of Toucan is shown in the figure below:



Figure 2.1: Toucan context

At its core, Toucan is the set of data and applications needed to develop and manufacture spectroscopes, notably:
* Announcement
* Create the optical plan using the Lines Configuration Software (LCS),
o including managing the Master Knowledge (OES, XRF, UniQuant).
* Test and calibrate the resulting instrument to the customers use cases
o including management of samples,
o including creation of reports.
* Maintain/track the whole installed-base of instruments,
o Including generation of statistics

2.2 Intended users & stakeholders
Intended users are captured as Actors in Section 3.2 Actors.

2.3 User environment
Toucan is used within departments of Thermo Fisher Scientific. Part of Toucan must be used outside of Thermo Fisher Scientific : for sales support (OES Optical layout creation, XRF instrument configuration). Users must use credentials to launch Toucan, and based on the associated roles, have (limited) access to functionalities.

Use Case
CRS_UC_QCOES_001 : Perform QC on OES
Actors
Manufacturing
Goal of Primary Actor
Ensure that all sensors work (individually)
Precondition
Instrument has been built and analytical software has been set up correctly for the QC tests.

Post condition
Instrument is ready to enter QA

Main Flow
1. From the Master Knowledge, Toucan creates QC programs (quality) in the Analytical software with default values to perform test: i.e. HVPS, CCD calibration
2. Toucan provide a checklist of every steps that must be performed. The order of steps in this checklist depends on the components used. OI-0033: more details are needed on the generation of checklist for QC in OES
3. Manufacturing performs QC tests using provided programs to validate or update instrument parameters; 
4. Every intermediate QC tests results must be traced until the shipment of the instrument.
5. Once instrument is shipped, only final QC tests values have to be traced in Toucan.
Alternative Flow Rare sample
The QC Plan may be adapted with knowledge from the upcoming QA Plan. Any such change will be traced.
Alternative Flow EasySpark
QC for instruments differs depending on components that have to be tested.
For example QC steps for easySpark CCD and iSpark CCD are different.
Each instrument can have its own QC plan based on what components compose it
Alternative Flow QC fails
1. If QC fails, then the instrument troubleshoot has to be done to identify the problem.
2. QC step is re-started.
Non-functional
QC Knowledge is managed by site. Brno knowledge used on an instrument in Brno, Ecublens knowledge used on an instrument in Ecublens

3.11 Use-case CRS_UC_QA_001 Perform QA on OES
Use Case
CRS_UC_QA_001 : Perform QA on OES
Actors
Manufacturing
Goal of Primary Actor
Ensure that all sensors and actuators work together and are capable of reaching the intensities required to meet the analytical plan.
Precondition
Instrument has passed QC

Post condition
Instrument is ready to be calibrated

Main Flow
1. Manufacturing uses Toucan to import in the analytical software the correct analytical program 
2. Based on Master knowledge and instrument configuration, Toucan creates, in the analytical software, a batch of samples that must be analysed to perform the QA Test
3. Manufacturing analyses every samples provided by Toucan
4. Manufacturing makes Toucan to process analysis results to calculate BEC & DL

6. Toucan stores all analysis- and test-results (matching or not).

If the ranges are not met (last step in main flow), then Manufacturing will troubleshoot, fix, and rerun the Main flow. This rerun may only need a few samples to be re-analysed, depending on the lines affected by the fix.

3.13 Use-case CRS_UC_CALIB_001 Perform Calibration
Use Case
CRS_UC_CALIB_001 : Perform Calibration
Actors
* For XRF : Manufacturing
* For OES: Manufacturing
Goal of Primary Actor
Ensure that the instrument is properly calibrated to the Customers needs (as expressed in  the Analytical Plan)
Precondition
Instrument has passed QA

Post condition
Instrument is ready to be validated

Main Flow
1. Manufacturing uses Master Knowledge to create the Calibration Plan for the instrument (which samples are to be analysed to calibrate the instrument?)
* Every line needs different samples to get different intensities (representing different concentrations)
* Up to 100 samples may be needed in this phase (even more)
2. Toucan creates in the analytical software a batch of analyses to be performed (samples list + analytical method to use + Task)
3. Once samples analysed Toucan gathers results (no raw data)
4. Toucan feeds the results through mathematical corrections and then the MVR algorithm to determine the calibration curve.
5. Toucan sends information (interferences, samples, segments) to analytical software 
6. The analytical software recalculates every MVR curves using Toucan information.
7. Manufacturing has to apply line choices in the analytical software.
Alternative Flow tweak MVR 
Manufacturing can manually tweak the input to MVR by selecting corrections, dropping outliers, etc.
Alternative Flow Chameleon
(note: this is on easySpark only!)
1. Toucan invokes the Chameleon module to create a smart subset of samples to be measured.
2. Chameleon sends the batch to analytical software and waits for results
3. Chameleon interprets the measured spectra, 
4.  and creates interpolated analyses
5. Toucan receives the dataset from the Chameleon module, and continues as if this set came from OXSAS.
Alternative Flow XRF UniQuant
An XRFs calibration is completely run on the instrument PC in the Analytical SW, but Toucan must receive the resulting parameters for storage and reporting.
Note that calibration of XFR is optional: the Customer may decide to do calibration by himself.
Alternative Flow XRF Quantas
An XRFs calibration is completely run on the instrument PC in the Analytical SW, but Toucan must receive the resulting parameters for storage and reporting.
Note that calibration of XFR is optional: the Customer may decide to do calibration by himself.
Alternative Flow XRF MVR
OI-0045: How is MVR on XRF?
Non-functional
This must reuse the DLL that is currently available for performing MVR (see CRS.INT.03)

4. on validation of the comment, user must define if the change is standard/postponed/Urgent or has to be applied later
5. User selects Standard.
6.  The change is released after the Toucan Backup has been performed
Alternative Flow Urgent change 
1. A Change has to be performed in the Master Knowledge
2. R&D Analytical specialist performs the change 
3. Use-case Track Master Knowledge changes
4. on validation of the comment, user must define if the change is standard/postponed/Urgent or has to be applied later
5. User selects Urgent.
6. The change is immediately done & tracked.
Alternative Flow Release postponed changes 
1. A Change has to be performed in the Master Knowledge
2. User performs the change 
3. Use-case Track Master Knowledge changes
4. on validation of the comment, user must define if the change is standard/postponed/Urgent or has to be applied later
5. User selects postponed.
6. A window allows the user to link the change to another one; this change will be postponed then as well (as will any change that it is linked to).
7. The change is recorded & tracked. 
8. User wants to apply pending changes. This user must have sufficient rights to do so: R&D modification (for quality creation for example) can only be released by a user from R&D
9. Toucan displays every pending changes
10. User selects a change and applies it
11. If change is linked with others, all its children are applied.
12. Toucan traces who has released the change, and requests a Release Reason.

Requirement description

The following operations on the data must be traced to who made the update. Every modification must contain:
* A reason for the modification
* The owner of the modification
Rationale: the Master Knowledge is vital to Thermo Fisher Scientific.

The trace must be stored in the Toucan database; there is no need to cryptographically ensure that this trace cannot be modified (i.e., non-repudiation)

Requirement description
Origin

Business logic in Toucan is the same as in CARL: when calibrating in either application, the resulting calibration curve is the same (when same settings are applied)
Rationale: the Master Knowledge is vital to Thermo Fisher Scientific
